# Epochal

Clients for the [Epochal](https://epochal.com) API: Rust crates, Python packages, an MCP server and
a CLI. `epochal-api` and `epochal-sandbox` are on both crates.io and PyPI under those names;
`epochal-mcp` and `epochal-cli` are Rust only.

Their one module today is the **Time Portal**, which serves the web, and Linux sandboxes, as they
stood at a past instant. Search and fetch return only what was published and crawled by then; a
sandbox's clock starts there and its network sees nothing later. Use it to test an agent or a
forecast against the past, with nothing from after that instant leaking in. In each package the
Time Portal is named as such: `client.time_portal(as_of)`, `Sandbox::time_portal(as_of)`,
`epochal-mcp --time-portal`, `epochal time-portal`.

| Directory | Package | What it is |
|---|---|---|
| [`api/`](api) | `epochal-api` (Rust) | One method per API call; for the Time Portal, web search, web fetch, and the raw sandbox calls |
| [`sandbox/`](sandbox) | `epochal-sandbox` (Rust) | Sandboxes: build one, run commands, move files, serve its ports from your machine |
| [`mcp/`](mcp) | `epochal-mcp` (Rust) | `epochal-mcp`, an MCP server giving an agent `web_search` and `web_fetch` at an instant |
| [`cli/`](cli) | `epochal-cli` (Rust) | `epochal`: `epochal time-portal` runs an agent in a sandbox, or searches and fetches from the shell |
| [`python/api/`](python/api) | `epochal-api` (Python) | The API client, sync and async |
| [`python/sandbox/`](python/sandbox) | `epochal-sandbox` (Python) | Sandboxes, sync and async, with examples |

The pieces stack: the sandbox crates call the API crates; the MCP server uses the Rust API crate;
the CLI uses all three Rust crates. Each directory's README has its setup and examples.

## Quick start

Every package reads your API key from `EPOCHAL_API_KEY`; create one at
https://console.epochal.com/keys. `EPOCHAL_BASE_URL` overrides the API address (default
`https://api.epochal.com`). An instant written as a bare day, `2025-03-12`, means 23:59:59 UTC that
day, as the API reads it.

```sh
export EPOCHAL_API_KEY=...

# From the shell:
cargo install --path cli
epochal time-portal search "fed rate decision" --as-of 2025-03-12
EPOCHAL_LLM_BASE_URL=https://api.anthropic.com EPOCHAL_LLM_API_KEY=... \
  epochal time-portal run --model claude-sonnet-5-5 --as-of 2025-03-12 \
  "Summarize the Fed's latest rate decision"

# As an MCP server for your agent:
cargo install --path mcp
epochal-mcp --time-portal 2025-03-12 --serve http:8788   # streamable HTTP at /mcp

# From Python:
pip install epochal-sandbox
python -c 'from epochal.sandbox import Sandbox
with Sandbox.time_portal("2025-03-12").build() as box:
    print(box.command(["date", "-u"]).output().text)'
```

From Rust, `cargo add epochal-sandbox` (or `-api`); [`sandbox/`](sandbox) and
[`api/`](api) have complete examples.

## Development

The Rust crates are one Cargo workspace, pinned to Rust 1.88 by `rust-toolchain.toml`:

```sh
cargo test --workspace            # unit, integration and README examples
cargo clippy --workspace --all-targets
cargo fmt --check
```

The Python packages are one [uv](https://docs.astral.sh/uv/) workspace under `python/`:

```sh
cd python
uv run pytest                     # every test runs against the sync and async flavours
uv run ruff check . && uv run ruff format --check .
uv run mypy
uv run python scripts/unasync.py  # after editing an async module or the sync client
```

Each Python package has one hand-written flavour and one generated by `scripts/unasync.py`: the
async sandbox and the blocking API client are the sources. A test fails if a generated file is
stale.

Tests run against fake API servers in-process, so they need no key and no network.
